# تدريب موديل تسميع مُتقِن

الدورة كلها بين الـ**Worker** و**Colab** — تطبيق اليوزر ملوش دعوة:
هو بس بيرفع داتا التسميع للـ Worker (اللي يخزّنها R2)، وبينزّل الموديل الجاهز.

```
تطبيق اليوزر ──رفع──▶ Worker/R2 ──/data──▶ Colab (تجهيز + تدريب + تصدير)
تطبيق اليوزر ◀─/model── Worker/R2 ◀──/put── Colab (نشر الموديل الجديد)
```

## التشغيل

افتح `finetune_colab.ipynb` في [Google Colab](https://colab.research.google.com)،
اختار GPU، وشغّل الخلايا بالترتيب — هيطلب مفتاح الـWorker مرة واحدة (نفس
`SYNC_TOKEN`). كل حاجة بعدها تلقائية:

1. **prep.py** — يسحب الجلسات من الـWorker (`/data/list` + `/data/get`)،
   يغلّف الصوت WAV، ويبني `manifest.jsonl` — النص كلمات المصحف حيث أصاب
   القارئ وما قاله فعلًا حيث أخطأ، ويستبعد الجلسات الأقل دقة من `MIN_ACC`
   (الافتراضي 0.85).
2. **finetune.py** — يقسم الداتا ٩٠/١٠، يجيب الشيكبوينت الأساسي
   (`mohammed/fastconformer-quran-ar`)، ويدرّبه بمعدّل تعلّم منخفض
   (متغيرات: `EPOCHS`، `LR`، `BS`).
3. **export_int8.py** — تصدير ONNX (فرع CTC بمدخل log-mel كما يغذّيه
   التطبيق)، ضغط INT8، تقسيم مقاطع، **ونشر عبر `POST /put` بالمفتاح** —
   المقاطع أولًا والمانيفست آخر حاجة فلا يرى أي تطبيق تحديثًا ناقصًا.
   التطبيقات تكتشف التحديث وتستأذن المستخدم قبل التنزيل.

## ملفات مساندة

- `pages.json` — كلمات كل صفحة (١..٦٠٤) **بإملاء محرّك التطبيق نفسه**
  (٧٧٬٤٢٨ كلمة). مولَّد من كود التطبيق — لو قواعد التطبيع في المحرّك
  اتغيّرت، يتعاد توليده من ريبو التطبيق.
- `../collector/worker.js` — الـWorker المنشور: يستقبل رفع التطبيقات،
  يقدّم الموديل (`GET /model/*` عام)، ويخدم التدريب (`/data/*` و`/put`
  بالمفتاح). تعليمات نشره في رأس الملف.

## متى يفرق التدريب؟

الموديل الأساسي متدرّب على قرّاء مشاهير باستوديوهات نضيفة — التدريب على
أصوات المستخدمين الحقيقية (مايك موبايل، دوشة، سرعات مختلفة) يقلّل الأخطاء
الكاذبة ويثبّت التتبّع. بيبان مع ١٠+ ساعات صوت، ويتقاس بنسبة التحقق اللي
يطبعها التدريب قبل/بعد.
